# Scope — Bukana Brilliant Schools

## 1. Initial release

The initial release is a public-facing informational school website.

### Included
- Responsive homepage.
- About the School page.
- Academics page covering Creche, Nursery, and Primary.
- Admissions information page.
- School Life / Gallery page.
- Contact / Find Us page.
- Optional News & Events page only if the school supplies maintainable content.
- Responsive desktop and mobile navigation.
- Reusable page sections and UI components.
- Structured local content data.
- Approved school photography and brand assets.
- Page-specific SEO metadata.
- Accessible interaction states.
- 404 page.
- Production build and smoke checks.
- Deployment configuration once the hosting provider is confirmed.

## 2. Functional expectations

- Navigation routes to the correct pages.
- Admissions CTAs lead to a verified contact or enquiry route.
- Contact links use confirmed official details.
- Gallery images open or display in an accessible manner if a lightbox is implemented.
- Mobile menu opens, closes, and supports Escape.
- All interactive controls have clear feedback.
- No false form-submission success states.
- Direct route access and refresh work on the selected host.

## 3. Deferred pending owner decision

- Database-backed content management.
- Admin dashboard.
- CMS integration.
- Online application workflow.
- Enquiry form backend or email integration.
- Student or parent portal.
- Staff portal.
- School fees payment.
- Student records or attendance.
- Learning management features.
- Online examination or result portal.
- Timetable management.
- Push notifications.
- Analytics and advertising integrations.
- Multilingual content.
- Search across news or resources.

These features must not be added simply because they are common in school websites. They require explicit product approval and a separate technical/security plan.

## 4. Explicit exclusions for the first release

- Collecting or storing student records.
- Collecting sensitive student/guardian data.
- User authentication.
- Payment processing.
- Fake admissions availability.
- Invented school statistics, reviews, rankings, awards, or accreditation.
- Unverified curriculum or policy claims.
- Unapproved identifiable student photographs.
- Unmaintained news/event feeds.

## 5. Scope control

If a new feature is proposed:
1. Explain the user problem it solves.
2. Identify content, backend, privacy, and operational requirements.
3. State whether it changes the initial release.
4. Obtain owner approval.
5. Update this document and the relevant specification before implementation.

Do not silently expand scope.
